    Overview¶

    No single channel wins a role alone — the portfolio works because a reviewer can move from LinkedIn post → GitHub repo → resume line and find the same story told consistently at increasing depth.

    The Anchor Projects¶

    Two or three projects should do most of the narrative work across all channels, chosen for being genuinely strong rather than most-recent: currently, the nhecf regulatory reporting package (Project 22) and whichever flagship project (18 or 19) is furthest along are the strongest anchor candidates, since both have real substance behind them rather than blueprint-only status.

    Consistency Discipline¶

    If the resume says a project achieved X, LinkedIn should say the same X (possibly framed differently, but not contradicted), and the GitHub README should show the work behind X. Any drift between channels is a credibility risk with a technical reviewer who checks more than one source.

    Quarterly Portfolio Audit¶

    Per templates/portfolio-strategy-template.md, formally reviewed at the Monthly Board Meeting (channel currency check) and more deeply at Quarterly Review (does the narrative still fit, per docs/operating-system/quarterly-review.md).

    Checklist¶

    • [ ] Anchor projects chosen for strength, not recency
    • [ ] Same claims across resume/LinkedIn/GitHub for any given project
    • [ ] No channel is stale relative to the others
