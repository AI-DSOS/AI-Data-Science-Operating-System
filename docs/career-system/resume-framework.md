## Overview

The resume is the highest-stakes, lowest-bandwidth channel — a recruiter spends seconds on a first pass. This document sets the strategy; `templates/resume-template.md` is the fill-in shape.

## Positioning Strategy

Lead with the QA-to-DS transition as a *strength signal*, not a gap to explain. Twenty years of testing production systems means: knows what breaks in production, thinks about edge cases by default, and writes documentation and tests without being told to — all things typical DS candidates are weak on. The headline should make this connection explicit, not leave the reader to infer it.

## Version Strategy

Three tailored variants, per `docs/departments/career-brand-coach.md`'s target role types:
- **IB Tech Teams:** emphasize domain terminology fluency (KYC/AML, Basel III, MiFID II), production-quality engineering, and the QFR/regulatory-reporting project.
- **FinTech Startups:** emphasize speed, ownership, and the Vaagai venture as evidence of end-to-end product thinking.
- **AI/ML Consulting:** emphasize breadth across the 25-project portfolio and the ability to scope ambiguous problems (per `templates/business-problem-template.md`-driven work).

## What Gets Emphasized vs. Cut

**Emphasize:** any project result stated with an honest metric (per `docs/engineering-standards/machine-learning.md`), any production-grade deliverable (deployed, monitored, tested), the multi-agent QA orchestrator and `nhecf` package as evidence of shipped, non-trivial engineering.

**Cut or minimize:** generic bootcamp-completion claims without a concrete artifact behind them, any project still at "blueprint only" status (per `projects/README.md`) — don't list unimplemented projects as if they were shipped.

## Common Mistakes to Avoid

- Listing tools/frameworks without a project that demonstrates them
- Burying the QA background instead of framing it
- Inflated metrics that wouldn't survive a follow-up question in interview

## Checklist

- [ ] Headline makes the QA-to-DS strength connection explicit
- [ ] Correct variant used for the target role type
- [ ] Every listed project has a real, honest result behind it
- [ ] No skill listed without a demonstrating project
