## Overview

The 62-day bootcamp plan already distinguishes evening sessions from Sunday deep-dive sessions — this document makes explicit *why* that split exists and what protects it. A multi-part topic like "diagnostic residual analysis connected to a business decision" doesn't fit into a 30–60 minute interruption-prone evening slot; it needs the kind of contiguous focus a weekday evening after a full Synechron workday usually can't offer.

## What Qualifies as Deep Work Here

- Multi-part ML topics that build on each other within a single session (e.g. the logistic regression → threshold-shifting → business-decision-framing sprint sessions already completed).
- Portfolio project implementation requiring sustained context (architecture decisions, pipeline debugging) rather than a single isolated fix.
- Anything the Learning Mentor or Enterprise Project Architect explicitly flags as "don't split this across sessions."

## Protection Rules

- Deep Dive blocks are Sunday-only by default (per `time-blocking.md`) — weekday evenings, after a full workday, are not treated as reliable deep-work capacity even when free.
- No notifications, no context-switching to a second topic mid-block. One topic or one project per Deep Dive block.
- A Deep Dive block that gets interrupted partway is not counted as complete — log it honestly and either finish it the same day or explicitly reschedule, rather than marking the topic "covered."

## Signs a Session Wasn't Actually Deep Work

- Covered 3+ unrelated topics in one sitting
- No worked example completed from scratch by the end
- Confidence score in the journal entry is a guess rather than tested by actually doing something

## Decision Rules

- If a weekday evening genuinely has 2+ free hours (rare, but happens), it can be upgraded to a Deep Dive block for that day only — this is a conscious exception, not a standing change to the weekly map.
- Deep Dive blocks are never split to "make room" for a Build block on the same Sunday unless the Task Prioritization exception rule applies (e.g. a live recruiter conversation).

## Checklist

- [ ] Session covered one topic/project, not several
- [ ] A worked example or concrete artifact was produced, not just review
- [ ] Interruptions logged honestly if they happened
- [ ] Confidence score reflects tested understanding, not a guess
